## Лекция 9. Репозиторий, непрерывная интеграция и воспроизводимость

### 9.1. Репозиторий

Создан открытый репозиторий **https://github.com/1StPersona/NIRM-gamified-learning** (лицензия Apache 2.0). В нём собраны код прототипа, тесты, скрипты экспериментов, их результаты и тексты заданий по курсу.

| Каталог | Содержимое |
| --- | --- |
| `gamification/` | модель главы 2: индекс вовлечённости EI (`metrics.py`), опыт, уровни и значки (`progression.py`), рейтинг Эло и выбор задачи (`adaptive.py`) |
| `services/gamification_api/` | сервис FastAPI: событие «решение проверено», лидерборд, проверка состояния; хранилище в памяти или Redis |
| `tests/` | модульные и интеграционные тесты (pytest) |
| `simulation/` | калибровка шага K на синтетических студентах |
| `bench/` | микро- и макробенчмарки, построение отчёта, сырые результаты (`bench/results/`) и график (`bench/plots/`) |
| `docs/` | задания к лекциям 1–9 в Markdown и Word, иллюстрации |
| `.github/workflows/ci.yml` | конвейер непрерывной интеграции |
| `requirements.txt`, `Dockerfile`, `docker-compose.yml`, `Makefile` | окружение и команды запуска |

Версии всех зависимостей зафиксированы точно (`fastapi==0.162.2` и т. д.), поэтому через год окружение соберётся таким же. Случайность в симуляции управляется параметром `--seed`.

### 9.2. Непрерывная интеграция

Конвейер GitHub Actions запускается на каждый `push` и `pull request`:

1. Поднимается служебный контейнер **Redis 7.0** с проверкой готовности (`redis-cli ping`).
2. Устанавливается Python 3.13 и зависимости из `requirements.txt` (с кешем pip).
3. **Тесты:** `pytest -v`. Переменная `REDIS_URL` задана, поэтому выполняется и интеграционный тест с настоящим Redis.
4. **Воспроизводимость симуляции:** короткий прогон `python -m simulation.simulate --seed 42 --reps 1`. Шаг ловит ошибки, из-за которых эксперимент перестал бы запускаться.
5. **Микробенчмарк:** `python -m bench.micro`. Результат (`micro.json`) сохраняется как артефакт сборки. По нему можно отследить, если изменение кода заметно замедлило модель.

Значок состояния сборки выведен в начало README.

### 9.3. Тесты

Написано 35 тестов в 5 файлах (требование задания — не меньше трёх). Тесты проверяют формулы главы 2 и поведение сервиса.

| Файл | Тестов | Что проверяется |
| --- | --- | --- |
| `test_adaptive.py` | 6 | при равных θ и d вероятность успеха 0,5; успех повышает θ и снижает d, неудача наоборот; при равных K обновление с нулевой суммой; выбранная задача ближе всех к p* = 0,7; пустой каталог даёт ошибку |
| `test_progression.py` | 18 | базовый XP за решение с первой попытки; штраф за попытки; бонус серии ограничен; формула уровня обратна порогу для уровней 1–14 (параметризованный тест); значок выдаётся один раз; неверное число попыток отклоняется |
| `test_metrics.py` | 5 | доли активности и завершения; деление на ноль при отсутствии попыток; EI лежит в [0, 1] и упорядочен; сумма весов равна 1; нормализация обрезает выбросы |
| `test_api.py` | 4 | решённая задача даёт XP и меняет рейтинг; нерешённая не даёт XP; лидерборд отсортирован; некорректное событие отклоняется (422) |
| `test_api_redis.py` | 1 | XP и лидерборд сохраняются в Redis (запускается, если задан `REDIS_URL`) |

Результат локального запуска:

```
$ pytest -q
34 passed, 1 skipped
$ REDIS_URL=redis://127.0.0.1:6379/0 pytest -q
35 passed
```

Тесты закрепляют два граничных случая. Первый: формула уровня через логарифм на точной границе порога может из-за погрешности плавающей точки дать уровень на единицу меньше; код проверяет соседние уровни, а параметризованный тест проверяет все границы с 1 по 14 уровень. Второй: при равных расстояниях выбор задачи не должен зависеть от порядка словаря, поэтому ничья решается сортировкой по id.

### 9.4. Инструкция по воспроизведению

Раздел «Как воспроизвести» в README описывает три пути.

**Без Docker (Python 3.13):**

```
git clone https://github.com/1StPersona/NIRM-gamified-learning.git
cd NIRM-gamified-learning
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
make test        # тесты
make simulate    # калибровка K → bench/results/simulation.csv (≈1 мин)
make micro       # микробенчмарки → bench/results/micro.json
```

**С Docker:** `docker compose up -d --build` поднимает Redis и сервис на порту 8000. Затем `make load STORE=redis` и `make report`.

**Только проверка:** открыть вкладку Actions в репозитории. Каждая сборка показывает тесты, короткую симуляцию и микробенчмарк на чистой машине.

Ожидаемые результаты лежат в `bench/results/`. Числа нагрузочного теста зависят от машины. Сравнивать нужно соотношения: Redis медленнее хранилища в памяти примерно в 4 раза, а p95 при 64 клиентах меньше 100 мс.

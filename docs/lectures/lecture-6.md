## Лекция 6. Управление данными и артефактами

### 6.1. План управления данными (DMP)

**Какие данные собираются**

| Данные | Источник | Формат | Персональные? | Публикация |
| --- | --- | --- | --- | --- |
| Журнал событий (входы, попытки, вердикты, награды) | сервис аналитики, PostgreSQL | таблицы → экспорт в Parquet/CSV | псевдонимизированы | да, обезличенные |
| Исходный код решений студентов | сервис отправок, MinIO | текстовые файлы | может содержать имена в комментариях | нет, только метаданные |
| Результаты пре- и пост-теста | платформа | CSV | псевдонимизированы | да, обезличенные |
| Анкета мотивации | форма в платформе | CSV | псевдонимизированы | да, обезличенные |
| Контент: квесты, тест-кейсы, сложность | сервис контента | YAML/JSON | нет | да (кроме скрытых тестов пост-теста) |
| Параметры модели и симуляции (веса EI, K, p\*, seed) | конфигурации | YAML | нет | да |
| Скрипты анализа и графики | репозиторий | Python, Jupyter | нет | да |

**Документирование и метаданные.** Для каждого набора ведётся словарь данных (`data/README.md`): поля, типы, единицы, допустимые значения и связь с формулами главы 2. Схема событий RabbitMQ описывается Pydantic-моделями и экспортируется в JSON Schema. Временные метки — UTC, ISO 8601. Версия набора в имени файла: `events_v1.0_2027-03.parquet`.

**Предобработка.** Выгрузка и очистка делаются только скриптами из `analysis/pipeline/` (ручные правки запрещены). Правила исключения (тестовые аккаунты, студенты с менее чем одной сессией) фиксируются до начала анализа.

**Хранение и версионирование.** Рабочие данные хранятся в PostgreSQL и MinIO на сервере университета с ежедневной резервной копией. Экспортированные наборы версионируются через DVC с удалённым хранилищем в MinIO, код — через Git. Каждый результат в диссертации ссылается на тег репозитория и версию набора.

**Этика и право.**

- Перед запуском эксперимента — одобрение этической комиссии университета (если такая процедура есть — уточнить у научного руководителя).
- Письменное информированное согласие на обработку персональных данных по Закону РК «О персональных данных и их защите»; требования GDPR соблюдаются как ориентир (минимизация, право на отзыв). Участие добровольное и не влияет на оценки по курсу.
- Псевдонимизация при выгрузке: идентификатор Keycloak заменяется на HMAC-SHA256 с секретным ключом, ключ хранится отдельно и уничтожается после защиты. Имена, e-mail и точное время входов в публичный набор не попадают (время сдвигается к началу эксперимента).
- Исходный код студентов не публикуется: он может содержать персональные данные и является результатом их творческого труда.

**Публикация и долговременное хранение.** Код — на GitHub, релиз под статью архивируется в Zenodo с DOI. Обезличенные данные и словарь — отдельный запись Zenodo. План анализа и гипотезы предварительно регистрируются на OSF до сбора данных. Непубличные данные хранятся на сервере университета 5 лет после защиты, затем удаляются.

**Ответственные.** Магистрант — сбор, обработка, публикация; научный руководитель — контроль этических требований и доступ к ключу псевдонимизации.

### 6.2. Организация набора данных и кода

Монорепозиторий платформы дополняется исследовательской частью:

```
gamified-learning-platform/
├── services/            # FastAPI-сервисы: content, submission, judge, gamification, analytics, ...
├── frontend/            # React + TanStack Query
├── libs/                # общие схемы событий (Pydantic), утилиты
├── infra/               # docker-compose.yml, Traefik, Keycloak realm, .env.example
├── content/             # квесты и открытые тест-кейсы (YAML)
├── experiment/
│   ├── config/          # conditions.yaml (К/СГ/АГ), model.yaml (веса EI, K, p*), seed
│   ├── simulation/      # синтетические студенты для калибровки Эло
│   └── preregistration.md
├── analysis/
│   ├── pipeline/        # export → pseudonymize → clean → metrics
│   ├── notebooks/       # статистика и графики для главы 3
│   └── requirements.lock
├── data/                # только *.dvc-указатели + README (словарь данных)
├── Makefile             # make up / seed / simulate / analyze
├── CITATION.cff
├── LICENSE
└── README.md
```

Правила: никаких абсолютных путей и секретов в коде (только `.env`), все случайные числа через фиксированный seed, версии библиотек закреплены, версии образов Docker указаны тегами.

### 6.3. Инструкции по воспроизводимости (фрагмент README)

```markdown
## Воспроизведение результатов

Требования: Docker 24+, Docker Compose v2, Python 3.12, 8 ГБ RAM.

### 1. Запуск платформы
cp infra/.env.example infra/.env
make up        # docker compose up -d: все сервисы, Keycloak, PostgreSQL, RabbitMQ
make seed      # загрузка квестов из content/ и демо-пользователей
# платформа: http://localhost, вход student / student

### 2. Калибровка модели (без реальных данных)
make simulate  # experiment/simulation, seed из experiment/config/model.yaml

### 3. Анализ данных эксперимента
pip install -r analysis/requirements.lock
dvc pull data/events_v1.0.parquet   # или скачать с Zenodo (DOI в CITATION.cff)
make analyze   # таблицы и рисунки главы 3 → analysis/output/

Ожидаемый результат: файлы analysis/output/table_3_*.csv совпадают с таблицами статьи.
```

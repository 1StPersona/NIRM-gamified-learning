# Задание 2. Код и данные в репозитории, лицензии

Всё, что нужно для воспроизведения, лежит в открытом репозитории.

| Что | Где | Лицензия |
| --- | --- | --- |
| Модель геймификации, сервис, тесты (35) | `gamification/`, `services/`, `tests/` | Apache 2.0 (`LICENSE`) |
| Симуляции: калибровка K, сравнение политик, проверки устойчивости | `simulation/simulate.py`, `simulation/policies.py` | Apache 2.0 |
| Анализ и рисунки | `analysis/preliminary.py`, `paper/figures.py` | Apache 2.0 |
| Сырые результаты (CSV, JSON) и итоговая статистика | `bench/results/` | CC BY 4.0 (`bench/results/LICENSE-DATA.md`) |
| Статья (LaTeX, BibTeX, PDF) | `paper/` | Apache 2.0 для исходников; права на опубликованный текст переходят к издателю по условиям площадки |
| Доклад и постер | `presentation/` | Apache 2.0 |
| Как цитировать | `CITATION.cff` (GitHub показывает кнопку «Cite this repository») | — |
| Метаданные для Zenodo | `.zenodo.json` | — |

**Почему две лицензии.** Apache 2.0 подходит для кода: разрешает повторное использование, в том числе коммерческое, и даёт явную патентную лицензию. Для данных лицензии на программы не предназначены, поэтому результаты симуляций выпущены под CC BY 4.0: использовать можно свободно, ссылка на источник обязательна.

**Воспроизведение «с нуля»** (проверено в чистом окружении Python 3.13):

```
git clone https://github.com/1StPersona/NIRM-gamified-learning.git
cd NIRM-gamified-learning
pip install -r requirements.txt
make test          # 35 тестов
make policies      # три политики × 3 варианта симуляции, ~10 с
make analyze       # статистика → bench/results/preliminary_stats.json, рисунки → docs/img/
python -m paper.figures && cd paper && pdflatex main && bibtex main && pdflatex main && pdflatex main
```

Все случайные процессы управляются `--seed 42`, версии зависимостей зафиксированы, поэтому числа совпадают до последнего знака. Конвейер CI на GitHub Actions при каждом изменении запускает тесты и короткую симуляцию, то есть проверяет, что эксперимент по-прежнему запускается.

# Задание 3. DOI для артефактов проекта

DOI присваивается через интеграцию Zenodo с GitHub. Действия выполняются под учётной записью автора (Zenodo, CERN; бесплатно):

1. Войти на zenodo.org через GitHub (Log in → GitHub).
2. Открыть Account → GitHub, нажать Sync и включить переключатель у репозитория `NIRM-gamified-learning`.
3. На GitHub создать релиз: Releases → Draft a new release → тег `v1.0.0`, название «Версия к статье», описание — что входит в релиз. После публикации релиза Zenodo сам архивирует его и выдаёт два DOI: на конкретную версию и общий (concept DOI), который всегда указывает на последнюю версию.
4. Метаданные (название, автор, лицензия, ключевые слова) Zenodo возьмёт из `.zenodo.json`, который уже лежит в репозитории. Перед релизом стоит добавить ORCID в `.zenodo.json` и `CITATION.cff`.
5. Вставить значок DOI в начало README, DOI версии — в раздел Data Availability статьи и в `CITATION.cff` (поле `doi`).

**Какой DOI где использовать.** В статье — DOI конкретной версии (`v1.0.0`), чтобы читатель получил ровно тот код и данные, по которым построены рисунки. В README и диссертации — общий DOI.

**Данные эксперимента со студентами** (после его проведения) получат отдельный DOI: обезличенный журнал событий публикуется на Zenodo или OSF отдельным набором данных, только если участники дали на это согласие.

# Задание 4. Рефлексия об этике и долгосрочном влиянии

**Этика.** До сих пор в проекте не участвовал ни один человек: все данные синтетические, и это снимало большинство этических вопросов. Они появятся вместе с экспериментом, и я вижу пять главных.

Во-первых, *добровольность*. Участники — студенты, а исследование проводится в их же университете. Студент может чувствовать, что отказ повлияет на оценку. Поэтому участие не должно влиять на оценку ни в одном условии, согласие собирает не преподаватель курса, а отказ можно дать в любой момент без объяснения причин. Во-вторых, *справедливость к контрольной группе*. Если адаптивная геймификация действительно помогает, контрольная группа четыре недели была её лишена. После эксперимента всем участникам открывается доступ к лучшему условию. В-третьих, *возможный вред от игровых элементов*. Лидерборды усиливают социальное сравнение, и есть данные о снижении внутренней мотивации \[6, 7\]. Поэтому лидерборд виден только внутри условия, и студент может его скрыть. В-четвёртых, *персональные данные*. Журнал событий хранит каждую попытку студента. В нём будут только псевдонимы, таблица соответствия хранится отдельно у руководителя и уничтожается после анализа, а работа с данными соответствует Закону РК «О персональных данных и их защите». Перед публикацией набор данных проверяется на возможность повторной идентификации: редкие сочетания признаков удаляются или огрубляются. В-пятых, *одобрение*: протокол проходит этический комитет университета до начала набора, а план анализа регистрируется на OSF, чтобы исключить выбор удобных результатов.

К добросовестности относятся и два вопроса, которые касаются уже сделанной работы. Первый — *честность результатов*: в статье опубликованы отрицательный результат (холодный старт) и ослабление выигрыша Эло при проверке устойчивости, хотя без них статья выглядела бы сильнее. Второй — *авторство и раскрытие помощи*. Вклад научного руководителя должен быть признан соавторством или благодарностью по договорённости с ним. Использование ИИ-ассистента при написании кода и текста раскрывается в разделе благодарностей, как требует политика IEEE, а ответственность за каждое число и утверждение остаётся за автором, поэтому все числа воспроизводимы из кода.

**Долгосрочное влияние.** Сама статья — небольшой вклад, а повторно использоваться могут три вещи. Первое — *симулятор политик выбора задач*: он позволяет любой команде, которая строит адаптивную систему, до эксперимента проверить свои параметры, найти проблему холодного старта и оценить, хватит ли случайных задач для честной оценки модели. Второе — *сервис геймификации* как отдельный компонент, который можно подключить к другой системе автопроверки кода через одно HTTP-событие. Третье — *обезличенный журнал событий* эксперимента: открытых данных о поведении студентов в геймифицированных курсах программирования мало, и такой набор полезен для сравнения моделей прогноза.

Чтобы это влияние было возможным, нужны не только лицензии и DOI, но и сопровождение. План такой: до защиты диссертации репозиторий активно поддерживается; после защиты он переводится в режим архива с явной пометкой в README, какие версии соответствуют статье и диссертации, и с указанием, что ошибки по-прежнему можно сообщать через Issues. Архив на Zenodo гарантирует, что код и данные останутся доступны, даже если репозиторий на GitHub будет удалён.
